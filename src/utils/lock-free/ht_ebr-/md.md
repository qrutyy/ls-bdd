Главное из анализа. Ядро агент не правил.

1. Серьёзно: вытеснение воркера посреди операции останавливает освобождение по всей таблице. В ядре Fedora стоит PREEMPT_DYNAMIC, и kthread вытесняется прямо внутри операции.
   - На прогоне так и вышло: при старом размере пула ht_concurrent_participants упал в 23 из 25 прогонов, пул кончался.
   - С preempt_disable() вокруг операции отказов не стало, но тогда node_alloc спит под выключенной вытесняемостью.
   - Значит, есть два пути: вынести node_alloc из операции (end → alloc → begin → повторный lookup) либо перейти на RCU/SRCU.
2. Средне: возможен use-after-free в lsv_ht_free. atomic_dec(&reclaim_pending) (ebr.c:221) ничего не упорядочивает, а ожидание в lsv_ht_free — обычный atomic_read. На arm64 запрос может дописать в уже освобождённый блок. Исправление простое: smp_mb\_\_before_atomic() перед dec и atomic_read_acquire() в цикле ожидания.
3. Средне: lsv.ko поверх ht_ebr- не соберётся. src/utils/ds_control.c:451 вызывает lsv_ht_insert_node, которого здесь нет, а ds_control.c:127,148 заполняют .node_copy. Сам lf_list_insert остался без вызовов и даёт warning, а с CONFIG_WERROR — ошибку сборки.
4. Средне: ячейки бездействующего потока не возвращаются. Его буфер освобождается только по запросу при no_cell. Если аллокатор никогда не отказывает, ретайрнутое потоком, который больше не работает с таблицей, висит до lsv_ht_free.
5. Мелочи:
   - Off-by-one в консервативную сторону: можно освобождать при retire_ts <= min_ts.
   - Локальные записи не выровнены по кэш-линии.
   - 64 байт мало для 128-байтных линий Apple Silicon.
   - Нет WRITE_ONCE для retire_cnt, KCSAN будет ругаться.
   - ht_kunit_cell_reached вызывается на каждом шаге обхода и без KUnit.
   - nr_threads включает уничтоженные воркеры: в тестах 89–277 записей на каждую операцию. Это ещё один довод за глобальный счётчик вместо max по записям.

Ядро безопасности агент проверил по LKMM и считает корректным. Устаревший ts при begin, одна метка на span, ранняя остановка скана, скан после end и Harris-операции тоже корректны.
